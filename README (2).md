# [팀명] Qure
> 보건실에 학생이 몰리거나 선생님이 자리를 비웠을 때, 학생이 태블릿으로 증상을 미리 적으면 선생님이 급한 학생부터 볼 수 있게 돕는 웹 문진표

## 1. 문제

**문제 한 문장:** 쉬는 시간에 보건실이 붐비거나 선생님이 자리를 비우면, 아픈 학생은 상태를 알리지 못한 채 기다리고 선생님은 누가 더 급한지 바로 알기 어렵다.

**상황:** 학생이 다치거나 아픈 일은 언제든, 한꺼번에 생긴다. 선생님은 한 명씩 말로 물어보며 순서를 정해야 해서, 그동안 더 급한 학생이 뒤에서 기다릴 수 있다.

**근거:** 주변 친구들에게 물어본 결과, 쉬는 시간에 보건실이 자주 붐비고, 점심시간이나 7교시 이후 보건실이 닫혀 아픈 것을 참은 적이 있다는 답을 들었다.

## 2. 해결

**핵심 시나리오:** 학생이 태블릿에서 응급 증상 확인 → 학번 입력 → 사람 그림에서 아픈 곳 선택 → 증상·통증·체온 입력 → 제출 후 "대기 N번" 확인 → 선생님이 급한 순으로 정렬된 대기열에서 확인하고 처치 승인 → 학생 태블릿에 결과 표시

| 구분 | 기능 |
| --- | --- |
| 필수 | 응급 신호 먼저 확인(있으면 바로 선생님께 알리라는 화면), 7단계 문진, 빨강·노랑·초록 등급 분류, 선생님 대기열 |
| 선택 | 추천 처치 승인, 대기 번호, 반별 유행 경고, 재방문 기록, 상담 알림, 통계 |
| 제외 | 병명 진단, 약 자동 결정, 학생 로그인, 학교 시스템 연동 |

**이 앱만의 기능**
- **사람 그림으로 아픈 곳 고르기:** 말로 설명하기 어려운 부위도 손가락으로 바로 알린다.
- **대기 번호표:** 제출하면 내가 몇 번째인지 보여 준다.
- **선생님 답장:** 선생님이 추천 처치(아이스팩, 밴드, 침대 휴식 등)를 승인하면 학생 화면에 바로 뜬다. 약은 선생님이 직접 건네거나 위치를 알려준다.
- **반별 유행 경고:** 오늘 같은 반에서 비슷한 증상 학생이 3명 이상이면 선생님 화면에 알린다.
- **통계:** 증상, 학년·반, 시간대, 다친 장소를 기간별로 보여 준다.
- **기록 자동 정리:** 방문 기록은 3년, 학생 사전 등록 정보는 한 학년도만 보관하고 자동으로 지운다.
- **자동 초기화:** 2분 동안 아무것도 누르지 않으면 "아직 쓰고 있나요?"를 묻고, 30초 뒤 답변을 지운다. 다음 학생이 앞 학생의 답을 보지 못하게 한다.

**완성 여부**
- [x] 응급 신호 확인과 7단계 문진
- [x] 등급 분류와 선생님 대기열
- [x] 추천 처치 승인, 대기 번호, 반별 유행 경고, 통계
- [ ] GitHub Pages에서 기록 저장 (4절 참고)

## 3. 설계

**화면 흐름**
- 학생: 개인정보 안내 → 응급 증상 → 학번 → 아픈 곳 → 증상 → 통증·체온 → 건강 상태 → 확인 → 완료
- 선생님: 비밀번호 → 대기열 / 방문 기록 / 학생 등록 / 통계

**데이터 구조:**

```
visits: 학번, 접수 시각, 등급, 응급 여부, 증상, 통증, 체온, 장소·경위, 상담 원함, 처리 상태, 추천 처치
profiles: 학번, 알레르기, 질환, 메모
```

**기술 선택:**
- 선택: HTML·CSS·JavaScript 한 파일. 설치 없이 태블릿 브라우저에서 열린다. 저장은 Claude 아티팩트의 공유 저장소를 써서 학생 태블릿과 선생님 PC가 실시간으로 같은 기록을 본다.
- 고르지 않은 안: 구글 폼은 응급 시 멈추기, 등급 정렬, 처치 답장을 만들 수 없다. Firebase 같은 서버는 하루 안에 설정하기 어려웠다.
- 막히면: 저장에 실패해도 학생 화면에 등급이 붙은 요약을 보여 주고 "선생님께 보여 주세요"라고 안내한다.

## 4. 실행 링크·실행 방법

- 실행 링크: https://gws072.github.io/solvathon-qure/
- 실행 방법: 링크를 열고 "동의하고 시작하기"를 누른다. 학번은 가짜 번호(예: 99999)를 쓴다. 선생님 화면은 제목을 빠르게 5번 누르고 비밀번호를 입력한다(발표 때 안내).
- 주의: 저장 기능은 Claude 아티팩트 안에서만 동작해서, GitHub Pages에서는 학생 문진까지만 볼 수 있다. 선생님 대기열은 아티팩트판(가짜 예시 기록)으로 시연한다.

## 8. 한계와 다음 계획

### 어려움: 개인정보 문제

완성 후 "진짜 학생 기록을 넣어도 안전한가?"를 따로 점검했고, 문제 16개를 찾아 개인정보보호법 조항과 맞춰 봤다.

| 어려움 | 극복하려고 한 일 |
| --- | --- |
| 학생 태블릿에서도 모든 기록을 읽을 수 있다 | 원인(저장소가 "쓰기만" 권한을 지원 안 함)을 찾고 고칠 구조를 설계했다. 그 전까지는 **실제 학생 기록을 받지 않고 가짜 예시 기록으로만 운영**하기로 했다. |
| 선생님 비밀번호가 소스에 보인다 | 비밀번호를 "학생 실수 방지용 화면 잠금"으로 역할을 정하고, README·발표 자료에는 적지 않았다. |
| 친구 학번으로 장난 접수가 가능하다 | 첫 화면에 다른 학번 금지 경고를 넣었다. |
| 안내문에 보관 기간이 없었다 | 3년 보관을 적고, 3년 지난 방문 기록을 자동으로 지우는 기능을 만들었다. 보호자 연락처가 담긴 사전 등록 정보는 학번이 바뀌는 새 학년도(3월)에 자동으로 지운다. |
| 입력 중 자리를 뜨면 다음 학생이 답을 본다 | 무입력 자동 초기화를 만들었다. |

배운 점: **돌아가는 앱과 학생에게 써도 되는 앱은 다르다.** 건강 정보를 다루는 앱은 누가 무엇을 볼 수 있는지부터 설계해야 한다.

**한계:**
- 등급과 추천 처치는 정해 둔 규칙일 뿐 진단이 아니며, 보건 선생님 검토 전이다.
- 실제 학생에게 쓰려면 학교가 승인한 저장소와 로그인이 필요하다.

**다음 계획:**
1. 학교 승인 저장소로 옮기고 선생님 로그인 추가(학생 기기는 제출만)
2. 보건 선생님께 문진 항목과 등급 기준 검토받기
3. 선생님이 얼굴을 보고 누르는 본인 확인 버튼
